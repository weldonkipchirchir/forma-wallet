# Test round 3 — 24 October 2026

This pass combined a complete bounded-concurrency regression run, six new permanent adversarial tests, two independent agents, production compilation/release checks and a read-only check of the deployed site's public response headers. No production behavior was changed in this round.

## New permanent coverage

`src/signing-lifecycle.test.ts` pauses SOL and SPL operations independently during signing, signature verification and serialization. Each of the six cases locks the wallet while the operation is paused, resumes it and asserts rejection instead of returned signed transaction bytes. All six passed; a second reviewer inspected the tests and independently exercised equivalent races using actual SDK methods.

## Independent results

- Final complete run: **156/156 tests passed across 28 files** with `npm.cmd test -- --maxWorkers=2 --testTimeout=30000` (27.79 seconds).
- Signing reviewer: 18 targeted tests passed, covering six lock races, existing persist-before-broadcast and uncertainty cases, and a synthetic Ethereum same-nonce reproduction.
- State/recovery reviewer: 33 tests across five files passed, covering journal retention, network context, encrypted recovery, multichain signing and exact transaction amounts.
- Test runners were limited to one or two workers with 30-second per-test limits to avoid previous crypto-test timeouts under parallel load. A sandbox-only EPERM failure happened before the state review's tests started; the permitted rerun passed.

Temporary reviewer probes were renamed from `.test.ts` to `.probe.ts` after execution. Vitest discovers test files inside the Git-ignored `.release` directory, so leaving probes named `.test.ts` would make counts depend on local artifacts. Permanent coverage lives under `src`; the clean tracked baseline before this round was 150 tests.

## Confirmed protections

- Revoked native signing sessions cannot return SOL/SPL signed output after locking at any tested asynchronous stage.
- A failed durable submission write prevents broadcast; interrupted/uncertain broadcasts remain recorded rather than automatically retried.
- Native journal retention preserves pending/unknown entries, and refresh includes unresolved entries beyond the latest 20 resolved records.
- Automated encrypted-backup/password-change fixtures preserve expected network identities.
- Both network-switch controls use the Ethereum auto-refresh helper; generation guards prevent stale network completions from repainting a newer selection (source reviewed, not browser retested).
- TypeScript/Vite production build and release checks passed for seven artifacts. Existing third-party annotation and large-chunk warnings remain.
- Public deployed root returned HTTP 200 with restrictive script CSP, COOP/CORP `same-origin`, cache-control `no-store` and frame denial. This confirms observed response headers only, not deployment provenance or the safety of loaded application code.

## Confirmed open findings

1. **Ethereum nonce coordination:** two distinct valid Ethereum transactions using the same nonce both reached a fake broadcaster concurrently through the existing submission helper. Actual ETH/ERC-20 handlers lack a shared account send lock. This is now executable synthetic evidence for the previously reported coordination gap, not a claim that two conflicting transactions can both be mined. A complete fix must include Ledger and both journals.
2. **Incoming SPL history discovery:** prior confirmed wallet-only signature discovery remains unchanged; recipient token-account transfers can be missing.
3. **Solana expiry recovery:** expired/dropped unknown submissions can continue blocking new sends. The journal retention fix does not prove expiry or allow retry.
4. **Cross-tab lock UX:** the global native journal storage listener conservatively locks the current wallet even for another account's status refresh. No loss-of-funds exploit was identified; account-aware handling would need to preserve signing invalidation.

No new signing bypass or identity-recovery mismatch was demonstrated. That does not establish absence of vulnerabilities. No user secrets, real funds, physical Ledger, real mobile viewport or actual screen-reader announcements were used. No deployment or push was performed. Keep testnet-only while the transaction coordination and history/recovery gaps remain open.
